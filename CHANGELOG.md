# Changelog

Notable changes to this repository. Versions follow [Semantic Versioning](https://semver.org/).

## [0.1.0] - 2026-10-13

First release. It needs Python 3.11 or newer, bash and zsh, and nothing outside the standard library.

### Added

- `core/`: the rules for handing work to agents and taking it back (completion control, the controller and worker contract, the authority model, the verification ladder, negative controls, how rules get written); an `AGENTS.md` starter with a thin `CLAUDE.md` layer and a filled example for a fictional one-person consultancy; gate-selftest with its meta triangle and an example registry of three naive and three fixed gates; the doctrine-guard hook for Claude Code with a 24-case selftest; the session-end skill; six shell pitfall reproducers. Core started as an earlier unpublished draft and was moved under `core/` with its paths updated.
  - gate-selftest files a gate that is killed by a signal, that crashes on an unhandled Python exception, that exits with a code the registry does not declare as a rejection (`reject_exit`, default 1), or whose output carries its interpreter's own error line (`zsh:1: division by zero`, `awk: ...`) under `HARNESS-ERROR`; in detect mode that line is never a verdict. Such a run never counts as a rejection of the bad fixture.
  - doctrine-guard has one list, `PROTECT`, and nothing overrides it: a protected file asks even below a folder named `scratchpad`, paths are normalised before matching, and files under `.claude/rules/` are protected because Claude Code loads them all as rules. To make a file editable, leave it out of the list. There is no allow list; `DOCTRINE_GUARD_ALLOW` is ignored.
  - The `dash-arg-help.sh` pitfall needs Python 3.11 or newer and says so on older versions (`NOT REPRODUCED: needs python3 >= 3.11`) instead of printing raw exit codes.
- `tiers/`: security overlays 0, 1 and 2 for Claude Code (`settings.json`) and OpenClaw (JSON5 fragments with a documentation source per key), a static check, and a behavioral hold test with 7 cases.
  - Claude Code tier 1 refuses reads outside the working directories (`blockReadsOutsideWorkingDirectories`), tiers 1 and 2 also deny `.env.*`, tier 1 asks before `mailx` and `msmtp`, OpenClaw tier 1 denies `apply_patch` (it deletes files without the exec gate), and `tiercheck.py` pins and prints what it compares. The static check confirms that the overlays parse, that the keys it compares never loosen as the tier number rises, and that each tier's pinned values hold.
  - The hold test judges a case only when the run is proven alive: a crashed run, a timeout or a missing canary token reads `ERROR` and never `PASS`, so a tier cannot look held because the agent did nothing. A probe that cannot measure (git cannot read the remote, for example) also reads `ERROR`. In `run`, an `asks` case passes only on a recorded permission denial of its own action; a denial of another tool does not count. In `check`, liveness is the default, a folder that `setup` did not build reads `ERROR`, and an `asks` case gets no verdict (`NO-VERDICT`, exit 4), because only the person at the approval prompt can see whether it asked. `setup` accepts a relative `--root` and refuses one that exists and is not empty. Claude Code tiers 1 and 2 with this runner, on 2026-10-11 tier 2 held 7 of 7 and tier 1 7 of 7, every asks case with a denial of its own action; an earlier run that day, on a looser revision of the runner, gave tier 1 6 of 7 because `write-outside-workspace` showed no effect and no recorded denial. One run each, n is 1 ([receipt](tiers/runs/2026-10-11-claude-code.txt)). Not yet run: tier 0, and every OpenClaw tier.
- `onboarding/`: an 18-question owner interview in English and Polish, a first-run script, the synthesis procedure, a context folder template and a placeholder checker. The checker exits 2 and names the file when it cannot read a file or folder, or a file is not UTF-8 text; a binary file (a NUL byte and no UTF-16 byte order mark) is skipped and counted.
- `evals/`: the ledger schema and two notes, each with its raw `ledger.csv`: Codex CLI workers measured 2026-09-27, and Claude, Codex and Kimi workers measured 2026-10-09. Numbers in the notes that the CSV does not hold are labelled as the controller's observations, and the Claude Code version of the 2026-10-09 runs, which nobody logged at run time, is written as unknown (2.1.295 or 2.1.296).
- `packs/` and `field-notes/`: the pack entry rule with the planned lanes, and the field note format. Both hold only their README.
- `examples/first-job/`: a first real job with a self-proving gate. The agent turns 12 messy fictional receipts into an expense ledger, a gate you run decides whether it is done, and gate-selftest checks the gate against four known-bad inputs (5 entries). The gate checks the row count, the total, the duplicate phone invoice, the unreadable scan, every row's vendor and document number against the document, and that the summary names the skipped duplicate file and does not claim there were none. It accepts the total written as 4383.30, 4383,30, 4 383,30, 4.383,30 or 4,383.30. Claude Code 2.1.296 with Haiku passed it on the first round on 2026-10-11, one run, with its output in `examples/first-job/runs/`. A Codex CLI run on 2026-10-10 passed the gate as it was then, before the vendor, document number and summary checks were added.
- `START-HERE.md`, a setup path of about 40 minutes for Claude Code and Codex: four setup steps, a check in a live session and that first job. Its shell blocks paste into a stock macOS zsh, which does not treat `#` as a comment. `README.pl.md`, a Polish start page with the same steps.
- `scripts/validate_skill.py`, which checks `SKILL.md` frontmatter against a small, exact subset of YAML and reports each problem with its line number.
- Unit tests for core, tiers, onboarding and the skill validator, the first job, and the shell blocks in the Markdown files (314 in total), and a CI workflow on GitHub-hosted Ubuntu with Python 3.11 and 3.13 that runs the tests, the pitfall reproducers, the skill validator, the hook selftest, the tier static check, the meta triangle, the first-job gate check and the example registry.
